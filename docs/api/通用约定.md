# MCP 接口通用约定

> 本文档适用于 `docs/api` 目录下全部 MCP 接口（`POST /mcp`，JSON-RPC 2.0）。
> 各接口的业务参数与返回字段以对应文档及官方文档（https://open.sellersprite.com/api）为准，本文只描述**所有接口一致的公共行为**。

---

## 一、调用方式

```bash
curl --location 'http://<host>:18080/mcp' \
  --header 'X-API-Key: <your-api-key>' \
  --header 'Content-Type: application/json' \
  --data '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "<tool_name>",
      "arguments": { "marketplace": "US", "...": "..." }
    }
  }'
```

### 支持的 JSON-RPC 方法

| method | 说明 | 需要 X-API-Key |
|--------|------|----------------|
| `initialize` | 握手，返回 protocolVersion / capabilities / serverInfo | 否 |
| `ping` | MCP 标准健康探测/保活，返回空 `result: {}` | 否 |
| `tools/list` | 获取工具清单（含 inputSchema） | 否 |
| `tools/call` | 调用工具 | **是** |
| `notifications/*`（如 `notifications/initialized`） | JSON-RPC 通知（无 id），返回 HTTP 202 空响应体 | 否 |

> 客户端在 `initialize` 后发送的 `notifications/initialized` 通知、以及定期 `ping` 保活均为 MCP 协议标准行为，服务端已按 Streamable HTTP 约定实现。

## 二、统一响应包裹

所有工具的 `result` 统一为：

```json
{
  "code": "OK",
  "message": "成功",
  "data": { }
}
```

| 字段 | 说明 |
|------|------|
| `code` | `"OK"` 表示成功；失败时为错误码字符串（见「四、错误码表」） |
| `message` | 成功为 `"成功"`；失败为可直接展示的错误描述 |
| `data` | 业务数据；失败时为错误上下文对象（含 `hint` 处理建议）或 `null` |

- 历史版本中有 4 个工具（competitor_lookup / product_research / asin_competitor / asin_sales_trend）返回 `{isError, structuredContent, content}` 结构，**已废弃**，现与其余工具完全一致。
- `data` 中已剔除上游内部字段（`guestId`、`took`、`url`、`terminal`、`guestVisited` 等），调用方无需自行过滤。

### 失败时的 data 结构

```json
{
  "code": "UPSTREAM_ERROR",
  "message": "数据服务返回成功状态但数据为空(可能为查询配额耗尽或会话权限不足)",
  "data": {
    "upstreamCode": "OK",
    "httpStatus": 200,
    "hint": "数据服务查询配额可能已耗尽或会话权限不足，请联系管理员处理后重试"
  }
}
```

- 调用方/模型应根据 `data.hint` 决定下一步动作（重试、联系管理员等）。
- **安全约定：错误信息不暴露任何第三方数据源的名称、域名、内部存储键名等实现细节**；排查所需的上游地址等信息仅记录在服务端日志中。

## 三、returnFields 参数（全部工具可选）

用于按需返回字段，降低响应体积与上下文 Token 消耗。

| 项 | 说明 |
|----|------|
| 类型 | `string[]`（也兼容逗号分隔字符串，如 `"asin,price"`） |
| 必填 | 否；不传返回全部字段 |
| 作用范围 | 分页型接口作用于 `data.items` 的每个元素；单对象型接口作用于 `data` 本体 |
| 始终保留 | 分页字段（`page` / `size` / `total` / `pages` / `hasNextPage` 等）与 `marketplace` 不受裁剪影响，始终返回 |
| 取值 | 返回 `data.items` 元素（或 `data`）的字段名，如 `["asin","price","title","monthlySalesUnits"]` |
| 无匹配字段 | 元素返回空对象 `{}`，分页信息仍保留，不报错 |

### 示例

请求：

```json
{
  "name": "asin_detail_lookup",
  "arguments": {
    "marketplace": "US",
    "asin": "B0DGYGSLPW",
    "returnFields": ["asin", "price", "title"]
  }
}
```

响应（item 仅保留指定字段）：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "page": 1,
    "size": 60,
    "total": 1,
    "items": [
      { "asin": "B0DGYGSLPW", "price": 15.29, "marketplace": "US", "title": "Amazon Basics ..." }
    ]
  }
}
```

## 四、错误码表

### 4.1 业务错误码（包裹在 result 中，HTTP 200）

| code | 含义 | data 内容 | 处理建议 |
|------|------|-----------|----------|
| `OK` | 成功 | 业务数据 | — |
| `BAD_REQUEST` | 业务校验失败 | `null` | 检查 message 提示后修正请求 |
| `UPSTREAM_ERROR` | 上游数据服务调用失败 | `{ upstreamCode?, httpStatus?, hint? }` | **按 `hint` 处理**（见 4.2） |
| `INTERNAL_ERROR` | 服务内部错误 | `null` | 友好降级，联系管理员 |

### 4.2 UPSTREAM_ERROR 的 hint 分类

| hint | 触发场景 | 下一步处理 |
|------|----------|-----------|
| 数据服务会话已失效，请联系管理员更新会话后重试 | 数据服务返回未授权/会话失效 | 联系管理员更新会话后重试 |
| 触发数据服务限流，请稍后重试或降低调用频率 | 数据服务限流 | 稍后重试、降频 |
| 数据服务查询配额可能已耗尽或会话权限不足，请联系管理员处理后重试 | 数据服务返回成功状态但 data 为空，或提示配额/套餐 | 联系管理员处理 |
| 数据服务响应超时，请稍后重试；如持续超时请联系管理员 | 请求超时 | 稍后重试 |
| 数据服务暂时不可用，请稍后重试 | 数据服务服务端异常 | 稍后重试 |
| 请联系管理员补充数据服务凭证后重试 | 该接口所需的数据服务凭证未配置（当前涉及 product_node / asin_sales_trend） | 联系管理员补充凭证 |
| 请检查请求参数后重试；如持续失败请联系管理员 | 其他数据服务错误 | 检查参数后重试 |

### 4.3 JSON-RPC 协议错误（error 字段，非 result 包裹）

以下错误返回标准 JSON-RPC `error` 对象，**不属于**业务包裹：

| code | 含义 | 说明 |
|------|------|------|
| `-32601` | Method not found | method 非 initialize / tools/list / tools/call |
| `-32602` | 参数错误 | 工具必填参数缺失（message 指明缺哪个），或工具名不存在 |
| `-32001` | missing API key | 缺少 `X-API-Key` 请求头 |
| `-32000` | 其他服务端错误 | 鉴权失败、限流、余额不足等网关层错误 |
