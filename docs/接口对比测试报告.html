一、全局性问题（影响多个接口）

1. 返回包裹结构不统一 不一致

同为 tools/call 的 result，两种格式混用：

格式 工具
{code, message, data}（17 个） asin_detail_lookup、keyword_miner、product_node、keyword_research、google_trend、traffic_keyword_stat、traffic_keyword、traffic_listing_stat、aba_research_weekly、aba_research_monthly、keyword_order、bsr_sales、asin_sales、market_research、keyword_conversion、traffic_extend、traffic_listing
{isError, structuredContent, content}（4 个） competitor_lookup、product_research、asin_competitor、asin_sales_trend

对同一个 MCP 客户端来说，调用不同工具需要两套解析逻辑，建议统一为其中一种（官方 API 是 code/message/data 风格）。

2. 官方 returnFields 参数未实现 功能缺失

官方文档明确说明 "MCP 可以通过 returnFields 参数选择性的返回某些字段，可以大幅降低上下文的 Token 量"。目前 21 个工具均未提供 returnFields 参数，且多数工具透传了大量上游额外字段（见问题 3），实际 Token 开销远大于官方 MCP。

3. 上游内部字段泄漏到输出 输出冗余

keyword_miner、keyword_research、keyword_order、keyword_conversion、aba_research_weekly/monthly 的 data 中透传了官方接口没有的分页/内部字段：guestId、guestVisited、terminal、took、url、hasNextPage。这些字段对调用方无意义，白白消耗 Token。

4. 数据库计费配置缺 8 个接口 配置缺失（已在测试环境补齐）

api_endpoint_pricing 表中缺少 8 条记录（schema.node.sql 里有 INSERT 但库中未执行）：TRAFFIC_KEYWORD_STAT、TRAFFIC_LISTING_STAT、TRAFFIC_LISTING、MARKET_RESEARCH、PRODUCT_NODE、ASIN_COMPETITOR、PRODUCT_RESEARCH、ASIN_SALES_TREND。缺配置时接口直接报错 接口未配置价格，完全不可用。测试时已在本地库补齐（成本值取自 schema.node.sql）。

5. 第三方会话配额耗尽时静默返回空结果 错误处理

测试过程中卖家精灵会话（Redis 中仅配置 1 个账号 13994443294）的 competing-lookup 查询配额耗尽后，上游返回 data: null，各工具不报错，返回 total=0 / items=[] 的"成功"结果，调用方无法区分"真的没数据"还是"会话不可用"。建议对 data === null 抛出明确错误。另外仅 1 个会话也无法体现"多账号轮询"的设计。

6. 4 个工具命名与官方 MCP Code 不一致 命名差异

接口 官方 MCP Code 我方工具名
ASIN 详情 asin_detail asin_detail_lookup
关键词反查(流量词列表) traffic_keyword traffic_keyword
BSR销量预测 bsr_prediction bsr_sales
ASIN 销量预测 asin_prediction asin_sales

其余 17 个工具名与官方一致。若目标是"模仿官方开放平台"，建议对齐命名。

二、逐接口对比明细

判定说明：✅ 一致 = 官方返回字段全部覆盖（允许少量额外字段）；🔴 结构差异大 = 字段命名/结构与官方明显不同；❌ 不可用 = 无法返回有效数据。

1. competitor_lookup（查竞品）monthName 映射 bug + 字段命名偏离

  • 输入 bug：官方参数 month（如 202607）被直接当作上游 monthName 传给卖家精灵 v3 接口，而上游 monthName 需要是 bsr_sales_nearly 或 bsr_sales_YYYYMM 形式。导致带 month 查询必然返回空。toMonthName() 里 String(month).replace('-','') 缺少前缀拼接（product_research 同）。
  • 输出字段命名（共用 competitionTransformer，与官方文档对比）：官方 units/unitsGr/bsrCr/bsrCv/revenue/ratingsRate/ratingsCv/ratingDelta/primePrice/dimension/dimensionsType/pkgDimensions/pkgWeight/sku 等，我方对应为 monthlySalesUnits/monthlySalesUnitsGrowthRate/bsrGrowthRate/bsrGrowthCount/totalAmount/reviewsRate/reviewsDelta/primeExclusivePrice/dimensions，且 缺失 brandUrl、nodeId、symbol、bsrId、sellerId、amzSales、amzUnitDate、dimension、dimensionsType、pkgDimensions、pkgDimensionType、pkgWeight、sku；多出 asinUrl、bigImageUrl、salesTrend、monthlySalesUnitsTrend、badgeBestSeller 等。
  • 注：因上游会话配额耗尽，未能取得该工具的实测数据，字段结论来自转换器静态分析（asin_competitor 实测输出证实了同一字段集）。

2. product_research（选产品）同 competitor_lookup 两项问题

  • 同样存在 month → monthName 映射 bug（带月份查询返回空）。
  • 输出共用 competitionTransformer，字段命名/缺失问题同上。
  • 输入参数覆盖较好：官方约 62 个参数基本都有（matchType、minPrice、badgeBS/AC/NR、fulfillment、sellerNation 等）。

3. asin_detail_lookup（ASIN 详情）字段齐但有 5 处映射 bug

  • subcategories 永远为空对象：上游返回数组 subcategories:[{rank,code,label}]（官方 API 也返回数组），转换器把它当单个对象处理（get(sub,'rank')），输出恒为 {"rank":null,"code":null,"label":null}，多子类目数据丢失。
  • zoomImageUrl 恒为 null：上游字段是 bigImageUrl，未映射。
  • primePrice 恒为 null：上游字段是 primeExclusivePrice，未映射（官方约定 -1 表示无 prime 价）。
  • firstRatingDate 恒为 null：上游字段是 firstReviewDate，未映射。
  • fulfillment 恒为 null：上游无同名字段（fba 是运费数字），未做转换。
  • 结构差异：官方 data 直接是 ASIN 对象；我方 data 是 {page,size,total,items:[...]} 分页包装。
  • ratings（评分数）：上游 competing-lookup 无此字段 → 恒 null；官方示例有值。features 五点描述同理（上游不返回 → 空数组），属于数据源能力差异。

4. keyword_miner（关键词挖掘）✅ 基本一致

  • 官方 30 个返回字段全部覆盖（marketplace、keyword、keywordCn/Jp、departments、month、supplement、searches、purchases、purchaseRate、monopolyClickRate、products、adProducts、supplyDemandRatio、avgPrice、avgRatings、avgRating、bidMin/bidMax/bid、cvsShareRate、wordCount、titleDensity、spr、relevancy、amazonChoice、searchRank、clicks、impressions）。
  • 多出字段：trends、monopolyAsinDtos、gkDatas、exactPpcItem/phrasePpcItem/broadPpcItem、absoluteRelevancy、searchWeeklyRank + 上游分页泄漏字段（建议清理或用 returnFields 控制）。

5. product_node（查产品类目）❌ 数据通道错误，恒返回 []

  • 该查询直接调用官方 OpenAPI api.sellersprite.com/v1/product/node，需要 secret-key，但会话数据里根本没有配置 secretKey（只有 cookie）→ 上游返回错误，代码静默吞掉，永远返回 []。
  • 与其他 19 个接口走 cookie 模拟登录通道不一致。asin_sales_trend 存在同样问题。
  • 建议：改为走卖家精灵 Web 端类目接口或本地 amz_category 表（项目里有采集脚本和表结构）。

6. keyword_research（关键词选品）入参命名差异 + 输出缺 2 字段

  • 输入参数名不一致：官方为 keywords（可选），我方改为 includeKeywords 且设为必填——按官方示例 {"keywords":"child"} 调用我方接口会直接报参数错误。
  • 缺少官方输入参数：departments、withYearlyGrowth、minSearchesCr/maxSearchesCr、minSearchMonthCv/Cr、minSearchNearlyCv/Cr、minAraClickRate/maxAraClickRate、minGoodsValue/maxGoodsValue、minRatings/maxRatings、minRating/maxRating。
  • 多出非官方参数：supplement、orderField/orderDesc（官方是 order 对象）、minYearlyGrowth、minGrowth/maxGrowth、keywordBidMatchType。
  • 输出缺少：clicks、impressions。其余官方字段（含 araAsinList、relationAsinList、searchDepartments、brands、categories、titleDensityExact、marketPeriod、hasBrandWord 等）均已覆盖。

7. google_trend（谷歌趋势）✅ 一致

  • 输入（marketplace、keyword、googleProp、monthly）与输出（marketplace、keyword、link、items[{time,value}]）均与官方一致。
  • 多出 range{week,month,quarter,half,year,threeYear,all} 对象（额外有用信息，无害）。

8. traffic_keyword_stat（流量词统计）✅ 一致

  • 输出 marketplace、asin、keywords、ranks、ads、calcTime、badgeCount{ns,ac,er,fs,hr,sb,sv,ad} 与官方完全一致，多出 status 字段。
  • 注意：用无数据的 ASIN 查询时返回全 null 的"成功"结果（如官方示例 ASIN B0DXTMS9NF 已无数据），未做提示。

9. traffic_keyword（关键词反查/流量词列表）✅ 一致

  • 输出结构 {marketplace, asin, total, items, stats} 与官方一致，官方 item 字段全覆盖（keyword、searches、purchases、purchaseRate、bid、badges、rankPosition、adPosition、searchesRank、searchesRankTimeFrom/To、latest1/7/30daysAds、supplyDemandRatio、trafficPercentage、trafficKeywordType、conversionKeywordType、calculatedWeeklySearches、impressions、clicks、naturalRatio、adRatio 等）。
  • 多出：spr、titleDensity、top3ClickingRate、top3ConversionRate、monopolyClickRate、topAsins、searchesTrend 等额外字段。
  • 输入多了 spr 等筛选，官方 month 参数已支持。

10. traffic_listing_stat（关联流量统计）asin 恒为 null

  • 结构 {marketplace, asin, relations, freeRelations, paidRelations, calcTime, items[{relation,count}]} 与官方一致。
  • asin 字段恒为 null：上游 multi-stat 接口不返回 asin，转换器未回填请求中的 asinList[0]，而官方 API 返回查询的 asin。

11. traffic_listing（关联流量列表）未能实测，输出共用转换器有命名差异

  • 输入参数（marketplace+asinList+relations 必填、variations、page、size、order）与官方参数表一致。（官方文档的 curl 示例写的是 includeKeywords/date，与其自身参数表矛盾，我方按参数表实现是对的。）
  • 输出共用 competitionTransformer → 字段命名/缺失问题同 competitor_lookup。
  • 上游配额耗尽，未能取得实测数据。

12/13. aba_research_weekly / aba_research_monthly（ABA 选品按周/按月）✅ 基本一致

  • 官方字段全覆盖（marketplace、date、keyword、keywordCn/Jp、departments、searchRank/Cv/Cr、searches、purchases、purchaseRate、clicks、impressions、titleDensityExact、cprExact、w1/w4/w12SearchRank 及增长率、top3Brands、bid/bidMin/bidMax）。
  • 小差异：官方 top3AsinDtoList 内每项含 {asin, imageUrl, clickRate, conversionRate, clickShareRate, cvsShareRate}，我方每项只有前 4 个，把 clickShareRate/cvsShareRate 提到了 item 层级。
  • 多出 searchRankGrowthValue/searchRankGrowthRate 及上游分页泄漏字段。

14. keyword_order（出单词反查）✅ 一致

  • 官方字段全覆盖（keyword、keywordCn/Jp、asin、searches、monopolyClickRate、cvsShareRate、searchRank、searchRankGv/Gr、top3ClickingRate、top3ConversionRate、conversionType）。
  • 多出 monopolyAsinDtos 及上游分页泄漏字段。

15. bsr_sales（BSR销量预测，官方名 bsr_prediction）🔴 输出结构与官方差异大

官方 我方
类目 categoryLabel category（另多出 categoryId）
预测日销 estDailySales dailySales
预测30天销量 estMonthSales monthlySales
明细列表 itemList[{bsr, estDailySales, estMonthSales}] rankSales[{rank, dailySales}]（缺 estMonthSales，bsr→rank）

16. asin_sales（ASIN销量预测，官方名 asin_prediction）🔴 输出结构与官方差异大

官方 我方
整体 asinDetail{asin,title,brand,availableDate,category,categoryId,imageUrl,ratings,rating} + dailyItemList[{date,bsr,sales}] {marketplace, asin, categoryId, category, monthlySales, dailyAmounts[], dailyPrices[], bsrs[]}
商品明细 有（标题/品牌/图片/评分） 无
日销明细 带 date 的结构化列表 三个平行裸数组（dailyAmounts/dailyPrices/bsrs），无日期对齐，数组下标语义需调用方自行推算

17. market_research（选市场列表）输入一致，输出缺约 20+ 官方字段

  • 输入：与官方一致（nodeIdPath、departmentKeyword、topNum、newProduct、minAvgUnits 等系列筛选）。注意官方有 month（筛选日期）参数，我方 schema 未暴露（官方 curl 示例用的 date 参数名亦与参数表不一致，属官方文档自身问题）。
  • 输出缺失的官方字段：currency、nodeId、nodeLabelPath、nodeLabelPathLocale、totalRevenue、avgVolume/baseAvgVolume、avgWeight/baseAvgWeight、avgProfit、ebcProportion、sellerNation、sellerNationLabel、sellerProportion、top10Images、top3/top5/top10/top20 Product/Brand/Seller 的 Sales/Revenue/Crn 系列、l1/l3/l6/l12New* 系列、searchToPurchaseRatio。
  • 多出非官方字段：monopolyRatio、topAvgUnits、topAvgRevenue、topAvgBsr、goodsCrn、brandCrn、sellerCrn、newCount、newProportion、returnRatio、avgReturnRatio。

18. asin_sales_trend（ASIN 销量趋势）❌ 数据通道错误，恒返回空

  • 与 product_node 同样直接调官方 OpenAPI /v1/asin/{market}/{asin}/sales-trend，需要 secret-key 但未配置 → 上游报错被吞，asin 全 null、salesTrendPoints 恒为空数组。
  • 输出结构本身（asin 对象 + salesTrendPoints[{month,price,averagePrice,parentUnitSales,childUnitSales,parentSalesRevenue,childSalesRevenue}]）与官方一致，问题纯粹在数据通道。
  • 返回格式也是 4 个 MCP-style 包裹之一（与其他 17 个不一致）。

19. asin_competitor（查询 ASIN 竞品数据）🔴 字段命名与官方差异大

  • 实测可用（返回 8 个竞品），但输出字段集是 competitionTransformer 的自定义命名，与官方文档差异同 competitor_lookup：
  • 缺失官方字段：symbol、bsrId、brandUrl、nodeId、sellerId、amzSales、amzUnitDate、revenue、ratingsRate、ratingsCv、ratingDelta、dimension、dimensionsType、pkgDimensions、pkgDimensionType、pkgWeight、sku。
  • 命名不同：units→monthlySalesUnits、unitsGr→monthlySalesUnitsGrowthRate、amzUnit→monthlySalesUnits、revenue→monthlySalesRevenue、bsrCr→bsrGrowthRate、bsrCv→bsrGrowthCount、primePrice→primeExclusivePrice、ratingsRate→reviewsRate、ratingDelta→reviewsDelta。
  • 多出：asinUrl、bigImageUrl、monthlySalesUnitsTrend、badgeBestSeller、sellerType、availableDays、firstReviewDate、listingQualityScore、variationNum 等。输入多了官方没有的 size 参数（无害）。

20. keyword_conversion（关键字转化率）✅ 一致

  • 官方 68 个返回字段全部覆盖：keyword/keywordCn/Jp、searches、clicks、purchases、searchConvRate、clickConvRate、searchesTrend/clickTrend/purchaseTrend、clickingRate、conversionRate、phraseCount，以及 phrase/exact/broad 的 Ppc/Cpa/Budget/Acos 和 avgProductPrice 的 {min,max,value} 结构、top3Asins、top10Asins。
  • top3Asins 内部字段比官方文档更详细（asin、imageUrl、position、price、products、rankIndex、rankPage、rating、reviews、title）。多出上游分页泄漏字段。

21. traffic_extend（拓展流量词）✅ 一致

  • 官方字段全覆盖（keyword、keywordCn、searches、purchases、purchaseRate、products、bidMin/bidMax/bid、badges、updatedTime、searchesRank 及时间范围、latest1/7/30daysAds、supplyDemandRatio、trafficPercentage、calculatedWeeklySearches、avgPrice、avgRatings、avgRating、titleDensity、spr、monopolyClickRate、top3ClickingRate、top3ConversionRate、relationVariationsItems）。
  • 多出 adPosition、rankPosition 等额外字段。
