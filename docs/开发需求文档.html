SellerData-MCP 项目开发需求文档

版本 v0.1（草稿，待陈总确认） · 整理日期 2026-08-18 · 整理人：小项（项目经理）
依据：docs/官网原型.html、docs/业务架构流程图.html

1. 项目定位

面向亚马逊跨境卖家的 MCP 数据网关平台：统一以 MCP 协议（及等价 REST API）对外提供选品与市场数据接口，聚合多家第三方选品软件的数据能力，让大模型 / AI Agent 以自然语言方式调用电商数据（查竞品、看 ASIN 详情、分析市场等）。

商业模式：点数（积分）计费 —— 用户注册送积分、按需充值，每次接口调用按定价扣点；缓存命中不扣点。

4.4 MCP 网关（backend 核心）

编号功能说明
F-17MCP 协议端点 /mcpJSON-RPC 2.0，支持 initialize / tools/list / tools/call，支持 SSE 流式响应
F-18HTTP API 端点 /api/v1/mcp/*与 MCP 共享同一套网关逻辑的 RESTful 接口
F-19工具注册表 tools.json集中维护 MCP 工具定义（名称/描述/JSON Schema 参数），新增工具免发版
F-20API Key 认证校验 X-API-Key，关联 user_account，未激活/非法 Key 拒绝
F-21限流Redis 滑动窗口（ZSET），默认 5 QPS/用户，可按会员等级调整；超限返回 429
F-22缓存键 = provider + 接口 + 参数归一化哈希（ASIN 大小写/顺序归一化，分页参数不参与）；命中即返回，不扣点不调第三方；TTL 默认 300s
F-23扣点计费按 api_endpoint_pricing 扣减余额并写 usage_record，事务保证一致性；余额不足拒绝
F-24第三方请求适配Adapter 将 MCP 参数翻译为选品软件原生请求（market/asins/monthName/order 等）
F-25会话轮询调度按 provider 从 Redis list 轮询多账号登录态（Round-Robin），负载均衡、故障隔离与熔断
F-26响应转换Transformers 将异构第三方响应重组织为标准 MCP 结构（字段重命名/类型转换/趋势数组化）

5. 非功能需求

类别要求（建议值，待确认）

合规支付资金流合规、用户数据保护、内容安全；见《安全架构与技术选型》风险章节

7. 关键业务流程

7.1 MCP 工具调用时序

  1. Client tools/call → MCP 协议端点接收调用（工具名 + 参数）
  2. API Key 认证：校验 user_account 状态必须 ACTIVE，否则拒绝
  3. 限流：Redis ZSET 滑动窗口，超限返回 429
  4. 缓存查询：命中即返回，不扣点不调第三方
  5. 会话轮询：按 provider 轮询选择登录态（cookie）
  6. 转发第三方：构造原生请求并发送
  7. Transformers 标准化：响应重组织为标准 MCP 结构
  8. 事务扣点 + 写 usage_record
  9. 写缓存（TTL 300s）
  10. 返回 JSON-RPC structuredContent，模型组织成自然语言答案

7.2 充值流程

用户选档 → 创建订单 → 微信支付 / 支付宝 → 回调验签 → 事务到账（余额 + 赠送 + 有效期 + 充值记录）
