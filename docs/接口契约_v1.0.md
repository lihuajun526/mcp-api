## 1. 总约定

| 项 | 约定 |
|----|------|
| Base URL | `http://<接口服务器 IP>/api/v1`（免备案；如走域名则替换为域名，前端经 `VITE_API_BASE_URL` 切换） |
| 传输 | JSON，`Content-Type: application/json; charset=utf-8` |
| 鉴权（用户侧） | 登录后颁发 Bearer Token，放入 `Authorization: Bearer <token>`；Token 有效期 7 天 |
| 鉴权（网关侧） | MCP/数据接口调用走 `X-API-Key`（后端网关范围，不在本契约用户端接口内，留档见 §8） |
| 时间 | ISO 8601，UTC：`2026-08-27T10:00:00Z` |
| 金额 | 分（整数），字段名含 `Fen` 后缀；点数（积分）为整数 |
| 分页 | 入参 `page`（从 1 起）、`pageSize`（默认 20，最大 100）；返回 `{ list, total, page, pageSize }` |
| 幂等 | 创建订单支持 `clientOrderId`（客户端生成，24h 内重复提交返回同一订单） |

### 1.1 统一响应包络

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 表示成功；非 0 为业务错误，`data` 为 `null`，`message` 可直接用于前端提示。
- HTTP 状态码与业务码联动：`400/401/403/404/409/422/429/500` 对应业务码前缀（见 §7）。
- 限流：网关侧超限返回 HTTP `429`，业务码 `42901`，附响应头 `Retry-After: <秒>`。

### 1.2 通用枚举

| 枚举 | 取值 | 说明 |
|------|------|------|
| `memberLevel` | `basic` / `advanced` / `custom` | 初级版 / 高级版 / 定制版 |
| `keyEnv` | `live` / `test` | 生产 / 测试密钥，前缀 `sk_live_` / `sk_test_` |
| `keyStatus` | `active` / `disabled` | 启用 / 停用 |
| `toolStatus` | `online` / `planned` | 已上线 / 规划中 |
| `orderStatus` | `pending` / `paid` / `failed` / `expired` / `refunded` | 待支付 / 已支付 / 支付失败 / 已超时关闭 / 已退款 |
| `payChannel` | 以聚合支付渠道到位后补充（预留 `alipay` / `wechat` / `other`） | 个人开发者主体收单 |

## 2. 认证（注册 / 登录）

### 2.1 注册 `POST /auth/register`

注册成功即登录，并赠送 100 积分（赠送数额以 `GET /billing/config` 为准，不硬编码）。

请求体：

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| `email` | string | 是 | 邮箱格式；未注册过 |
| `password` | string | 是 | ≥8 位，同时含字母和数字 |

返回 `data`：

```json
{
  "token": "eyJhbGciOi...",
  "expiresAt": "2026-09-03T10:00:00Z",
  "user": { "id": "u_1001", "email": "seller@example.com", "memberLevel": "basic", "points": 100 }
}
```

错误：`40001` 参数不合法；`40901` 邮箱已注册。

### 2.2 登录 `POST /auth/login`

请求体：`{ "email": string, "password": string }`
返回 `data`：同 2.1。
错误：`40102` 邮箱或密码错误（不区分具体原因）；`40302` 账号已禁用。

### 2.3 登出 `POST /auth/logout`

请求体：无。返回 `data: null`。服务端将 Token 加入黑名单。

### 2.4 当前用户 `GET /auth/profile`

返回 `data`：

```json
{
  "id": "u_1001",
  "email": "seller@example.com",
  "memberLevel": "basic",
  "rateLimitPerMinute": 40,
  "points": 1250,
  "status": "active",
  "createdAt": "2026-08-01T02:11:00Z"
}
```

`rateLimitPerMinute` 为当前等级限流配额（初级 40 / 高级 60，以服务端配置为准），官网与工作台文案统一口径「次/分钟」。

## 3. 密钥管理

> 安全约束：明文密钥仅在创建响应中出现一次，服务端只存哈希；前端不落地存储明文。

### 3.1 密钥列表 `GET /keys`

返回 `data.list` 元素：

```json
{
  "id": "k_9001",
  "name": "生产主密钥",
  "env": "live",
  "maskedKey": "sk_live_ab12********ef34",
  "status": "active",
  "createdAt": "2026-08-02T03:00:00Z",
  "lastUsedAt": "2026-08-26T09:30:00Z"
}
```

### 3.2 创建密钥 `POST /keys`

请求体：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | string | 是 | 1~32 字符，同用户下唯一 |
| `env` | `live` \| `test` | 是 | 生产 / 测试 |

返回 `data`（`plainKey` 仅此一次）：

```json
{
  "id": "k_9002",
  "name": "调试密钥",
  "env": "test",
  "plainKey": "sk_test_Xk92mA04pq77Lw31",
  "maskedKey": "sk_test_Xk92********Lw31",
  "status": "active",
  "createdAt": "2026-08-27T10:00:00Z"
}
```

错误：`40902` 名称重复；`42203` 密钥数量达上限（默认 10 个，可配）。

### 3.3 更新密钥 `PATCH /keys/{id}`

请求体：`{ "status"?: "active" | "disabled", "name"?: string }`（至少一项）。
返回 `data`：更新后的密钥对象（无 `plainKey`）。
错误：`40401` 不存在；`40902` 名称重复。

### 3.4 删除密钥 `DELETE /keys/{id}`

返回 `data: null`。删除不可恢复；近 30 天有调用记录的密钥要求请求头 `X-Confirm: true` 二次确认，否则返回 `42801 需要二次确认`。

## 4. 余额与用量统计

### 4.1 账户概览 `GET /account/overview`

```json
{
  "points": 1250,
  "memberLevel": "basic",
  "rateLimitPerMinute": 40,
  "month": "2026-08",
  "monthCalls": 320,
  "monthPoints": 2180,
  "monthAmountFen": 21800,
  "pointToFenRate": 10
}
```

- `monthAmountFen` = 本月消耗点数按折算比例换算的金额（展示用）；`pointToFenRate` 为 1 积分对应的分值（读后台配置）。
- 积分永久有效，无过期字段。

### 4.2 按接口消耗统计 `GET /usage/summary`

入参：`month=YYYY-MM`（默认当月）。
返回 `data.list`：

```json
[
  { "toolCode": "competitor_lookup", "toolName": "查竞品", "calls": 120, "points": 1200, "amountFen": 12000 },
  { "toolCode": "asin_detail_lookup", "toolName": "ASIN 详情", "calls": 200, "points": 980, "amountFen": 9800 }
]
```

缓存命中的调用不计入 `calls` 与 `points`（命中不扣点）。

### 4.3 扣点明细 `GET /usage/records`

入参：`month=YYYY-MM`（必填）、`page`、`pageSize`、`toolCode?`。
返回分页 `data.list` 元素：

```json
{
  "id": "ur_50012",
  "time": "2026-08-26T09:30:12Z",
  "toolCode": "competitor_lookup",
  "toolName": "查竞品",
  "points": 10,
  "maskedKey": "sk_live_ab12********ef34",
  "cached": false,
  "requestSummary": "asin=B0EXAMPLE&marketplace=US"
}
```

### 4.4 明细导出 `GET /usage/export`

入参：`month=YYYY-MM`。
响应：`Content-Type: text/csv`，文件流（非包络结构），列与 4.3 一致；超过 5 万行返回 `42204 数据量过大，请缩小月份范围`。

## 6. 订单与充值

### 6.1 创建充值订单 `POST /orders`

请求体：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `planId` | string | 是 | 来自 `GET /billing/plans` |
| `payChannel` | string | 否 | 渠道到位后启用；缺省返回全部可用渠道 |
| `clientOrderId` | string | 否 | 幂等键 |

返回 `data`：

```json
{
  "orderId": "o_20260827100001",
  "planId": "plan_1000",
  "planName": "入门包",
  "priceFen": 100000,
  "totalPoints": 1100,
  "status": "pending",
  "payChannels": ["alipay", "wechat"],
  "payParams": { "qrCodeUrl": "https://pay.example.com/qr/xxx" },
  "expiresAt": "2026-08-27T10:30:00Z"
}
```

- 订单 30 分钟未支付自动关闭（`expiresAt`）。
- 支付渠道信息由合作方接入聚合支付后确定，`payParams` 结构随渠道定稿（预计 9 月中旬）。
- 错误：`40402` 档位不存在或已下线；`40903` 重复订单（幂等键冲突）。

### 6.2 订单状态轮询 `GET /orders/{orderId}/status`

前端在充值弹窗内轮询（建议 3s/次，最长至 `expiresAt`）：

```json
{ "orderId": "o_20260827100001", "status": "paid", "paidAt": "2026-08-27T10:05:21Z", "points": 1250, "totalPoints": 1100 }
```

- `points` 为支付成功后账户最新余额；`totalPoints` 为本单到账（含赠送）。
- 状态机：`pending → paid | expired | failed`；`paid` 后不可回退（退款走 `refunded` 并冲减余额）。

### 6.3 充值记录 `GET /orders`

入参：`page`、`pageSize`、`status?`。
返回分页 `data.list` 元素（对应 F-11）：

```json
{
  "orderId": "o_20260827100001",
  "planName": "入门包",
  "payChannel": "alipay",
  "priceFen": 100000,
  "totalPoints": 1100,
  "status": "paid",
  "createdAt": "2026-08-27T10:00:01Z",
  "paidAt": "2026-08-27T10:05:21Z"
}
```

## 7. 错误码总表

| HTTP | 业务码 | 含义 | 前端处理建议 |
|------|--------|------|--------------|
| 200 | `0` | 成功 | — |
| 400 | `40001` | 参数不合法 | 表单定位提示 `message` |
| 401 | `40101` | 未登录或登录态失效 | 清本地态，跳登录页 |
| 401 | `40102` | 邮箱或密码错误 | 表单错误提示 |
| 403 | `40301` | 无权限 | 提示并返回 |
| 403 | `40302` | 账号已禁用 | 提示联系客服 |
| 404 | `40401` | 资源不存在 | 降级提示 |
| 404 | `40402` | 充值档位不存在/已下线 | 刷新档位列表 |
| 409 | `40901` | 邮箱已注册 | 引导去登录 |
| 409 | `40902` | 密钥名称重复 | 表单提示 |
| 409 | `40903` | 订单幂等冲突 | 拉取已有订单状态 |
| 422 | `42201` | 积分不足 | 引导充值 |
| 422 | `42202` | 订单已关闭/过期 | 提示并允许重新下单 |
| 422 | `42203` | 密钥数量达上限 | 提示删除旧密钥 |
| 422 | `42204` | 导出数据量过大 | 提示缩小范围 |
| 428 | `42801` | 需要二次确认 | 弹二次确认后携 `X-Confirm` 重试 |
| 429 | `42901` | 触发限流（次/分钟超限） | 按 `Retry-After` 提示 |
| 500 | `50000` | 服务内部错误 | 友好降级，不白屏 |

> 网关侧数据接口（`/mcp`、`/api/v1/mcp/*`）的 429 限流、余额不足拒绝等由后端按 §8 实现，错误结构沿用本包络。

## 8. 网关侧留档（后端实现范围，非本契约交付面）

- `POST /mcp`：JSON-RPC 2.0（initialize / tools/list / tools/call），SSE 流式，`X-API-Key` 鉴权。
- `REST /api/v1/mcp/*`：与 MCP 同逻辑的 HTTP 等价接口。
- 限流：60 秒滑动窗口，按等级配额（40/60 次/分钟），超限 429 + `42901`。
- 缓存：命中不扣点；扣点写 `usage_record`，余额不足返回 `42201`。
