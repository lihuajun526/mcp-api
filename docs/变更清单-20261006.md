## 一、测试结论

### 1. 功能测试（全部通过）
- MCP 协议：initialize / notifications(202) / ping / tools/list（46 个工具 = 21 本地 + 25 个 ss_ 代理）/ tools/call 全部正常。
- 爬虫通道真实调用：`asin_detail`（US/B07Z82895W）成功，耗时约 260ms。
- 代理通道真实调用：`ss_trademark_country_list` 成功，耗时约 330ms。
- returnFields 裁剪生效（裁剪后 item 仅含指定字段）。

### 2. 用户校验 / 限流 / 扣积分（全部通过）
- 缺少 API Key → JSON-RPC -32001；非法 Key / 禁用用户 Key → "API Key无效或用户已禁用"。
- 限流：60s 滑动窗口，qpm=3 时第 4 次请求被限流（429 / "请求过于频繁"）。
- 扣费：first_category 调用后 18450→18445（扣 5），sdx_usage_record 明细正确（tool_code/credits/provider/urid/month）。
- 积分不足：余额 3 调 5 分接口 → "积分余额不足"，事务回滚无脏数据。
- 并发 20 调用 product_node 全部成功；余额不足场景下并发扣费无超扣（FOR UPDATE 行锁生效）。
- 缓存：asin_detail 第二次相同调用命中缓存，不扣费、不调上游（100→95→95）。

### 3. 性能
- 本地库接口（product_node）串行 20 次：min=6ms / p50=12ms / p95=22ms。
- 并发 20 次墙钟 68ms。无性能瓶颈。
- 每次调用原来必查 1 次定价表，已加进程内缓存（见修改点 4）。

### 4. 观察项（未改动，供参考）
- 限流计数发生在工具分发之前，参数校验失败的调用也会消耗限流配额（与官方口径是否一致需确认）。
- tools/list 不鉴权（官方 MCP 同样不鉴权），ping/initialize 无需 Key。
- 测试时发现 18080 端口有一个更早启动的旧进程（PID 92250）在运行，已终止；请注意多实例并跑会导致 EADDRINUSE 或测到旧代码。

## 二、代码修改清单

### 1. `app/config.js` —— 缓存默认开启（行为变更，重点核实）
- 原：`CACHE_ENABLED === 'true'` / `CACHE_READ_ENABLED === 'true'`（不显式配置即为 false）。
- 改：`!== 'false'`（默认开启，与 README「缓存配置（可选，默认开启）」一致）。
- 影响：两套 env 文件都没配置 CACHE_*，此前缓存实际是关闭的；改动后部署即生效（TTL 300s，命中不扣费不调上游）。已实测命中逻辑正确。

### 2. `app/services/billingService.js` —— 定价进程内缓存（性能优化）
- getPricing 增加 60s TTL 的 Map 缓存，每次调用少查 1 次 `sdx_api_endpoint_pricing`。
- 影响：后台改价最长 60s 生效。扣费事务逻辑未动。

### 3. `app/routes/tools/asinCompetitorTool.js` + `app/utils/validation.js` —— size 校验补齐（枚举 20/60/100，默认 60）
- 原：size 直接透传，无上限（tools.json 声明 1~100 但代码不校验）。
- 改：复用项目统一的 resolveToolPageSize；在 validation.js 的 TOOL_PAGE_SIZES 登记 asin_competitor 档位 20/60/100、默认 60（与 competitor_lookup/product_research 同档）。非法值抛 -32602「size must be one of: 20, 60, 100」。已实测 size=30 / size=50 均被拒、size=60 通过校验。
- 影响：原先 1~100 任意值（如 30、50）不再接受。tools.json 已同步改为 enum [20, 60, 100]、default 60（见下方 tools.json 变更）。

### 4. `app/routes/tools/keywordResearchTool.js` —— month 校验补齐
- 原：`String(args.month).replace('-', '')` 直接透传，非法值（如 20251、abc）会带到上游；且只替换第一个 `-`。
- 改：归一化（去所有 `-`）后走 assertMonth 严格校验 yyyyMM，非法抛 -32602。

### 5. `app/routes/tools/keywordMinerTool.js` —— historyDate 校验补齐
- 原：直接透传。改：assertMonth 校验 yyyyMM。

### 6. `app/routes/tools/trafficExtendTool.js` —— historyDate 校验补齐
- 同上。

### 7. `README.md` —— 会话存储结构订正
- 原：会话写入 `mcp:session:SELLERSPRITE`「列表」。
- 改：订正为「哈希」（sessionService 实际使用 HKEYS/HGET，field=账号标识，value=会话 JSON，按 field 轮询）。

## 三、tools.json 修改清单（按接口）

原则：与代码实现对齐（实现支持的才声明，固定值不暴露），去除 AI 看不到的「见表 x.x / 附录」悬空引用，returnFields 示例改为真实存在的字段。

| 接口 | 修改内容 |
|---|---|
| aba_research_monthly | **新增 4 个筛选参数 minSPR / maxSPR / minClicks / maxClicks**（代码 RANGE_FIELDS 与官方 MCP 均已支持，schema 漏声明，additionalProperties:false 导致模型无法传入）；order 描述去除「见表2.4」 |
| product_research | dimensionType 描述内联 9 个枚举值及中文含义（原「见附录表 1.4」）；availableMonth 去除「见附录表 1.3」 |
| traffic_keyword | order / trafficKeywordTypes / conversionKeywordTypes 描述去除「表2.3 / 表2.0 / 表2.1」引用（枚举值本已内联） |
| keyword_research | order 去除「见表1.8」；marketPeriod 改为「S1~S12 分别对应 1~12 月旺季，逗号分隔」（原「见表1.7」） |
| aba_research_weekly | order 去除「见表2.4」 |
| traffic_extend | order 去除「见表2.5」 |
| asin_competitor | **size 由「1~100 任意整数」改为枚举 20/60/100、默认 60**（与用户确认的上游口径一致；代码侧同步登记 TOOL_PAGE_SIZES，见代码修改第 3 条） |
| 全部 19 个含 returnFields 的接口 | returnFields 示例由不存在的 `["asin","price","monthlySalesUnits"]` 改为各接口真实字段（如 asin 类用 `["asin","price","units"]`、关键词类用 `["keyword","searches","purchases"]`、bsr_prediction 用 `["bsr","estDailySales","estMonthSales"]` 等） |

已核对无需修改的点：
- 各接口固定值参数（如 traffic_keyword 的 exactly/ac/keywordBidMatchType、traffic_keyword_stat 的 forceReStat/limit、traffic_listing_stat 的 queryVariations、asin_detail 的 page/size/order 等）均未在 tools.json 中声明，符合「固定值不暴露」原则。
- google_trend 的 keyword 官方同样非必填，保持一致未改。
- 站点枚举（marketplace.enum）与 marketplace.js 的 TOOL_MARKETPLACES 权威表逐工具核对一致。
- size 档位（通用 20/50/100 默认 50；competitor_lookup/product_research/asin_competitor 20/60/100 默认 60）与 validation.js 的 TOOL_PAGE_SIZES 一致。
