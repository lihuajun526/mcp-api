## 1. 仍存在的问题（详细）

### 1.1 【P1】`competitor_lookup` / `product_research` 响应体无 `order` 字段

官方这两个工具的响应是 12 字段分页信封，**含 `order`**：

```
官方信封：guestId, pages, page, size, total, took, url, order, items, terminal, hasNextPage, guestVisited
本地实测：competitor_lookup hasOrder=false / product_research hasOrder=false
```

两者共用 `competitionTransformer.js`，返回结构为 `marketplace/page/size/total/pages/hasNextPage/items`（见该文件 `transformCompetitionResponse`）。
**建议**：补 `order`（从请求回显，可复用 `resolveOrder()`）。

---

### 1.2 【P1】`order.field` 无白名单校验（非法值穿透上游）

`competitor_lookup` / `product_research` 直接把 `args.order.field` 字符串发给上游，无枚举校验：

```
实测：order={field:'revenue'}（官方合法值是 reviews，不是 revenue）
返回：{"code":"SERVICE_ERROR","message":"数据服务返回错误: 处理请求出现错误,请稍后重试。",
       "data":{"upstreamCode":"ERR_GLOBAL_500","httpStatus":200,"hint":"请检查请求参数后重试；如持续失败请联系管理员"}}
```

**仍缺**：没有 `-32602` 白名单拦截，用户看不到「`revenue` 不是合法排序字段」这个真因。
**建议**：对 `order.field` 做白名单校验（参考 `traffic_listing` 的 `ORDER_FIELDS` 做法），非法值直接 `-32602`。

---

### 1.3 【P1】`traffic_keyword` 响应缺 `size` / `page`

```
本地实测顶层字段：marketplace, asin, total, items, stats     ← 无 size / page
官方分页信封：guestId, pages, page, size, total, took, url, order, items, terminal, hasNextPage, guestVisited
```

**建议**：补 `size`/`page` 回显（handler 已有 `limit`/`skip`，可直接回显 `size` 与请求页码）。

---

### 1.4 【P2】`traffic_listing` item 字段缺 16 个 + 2 个命名不一致

官方 item 48 字段（与 `competitor_lookup` 同体系），本地 34 个。

| 类别 | 字段 |
|---|---|
| 官方有·本地缺（16） | `bsrCv`、`bsrCr`、`amzUnit`、`amzUnitDate`、`amzSales`、`unitsGr`、`averagePrice`、`primePrice`、`lqs`、`pkgDimensions`、`pkgDimensionType`、`pkgWeight`、`dimensionsType`、`deliveryPrice`、`subcategories`、`symbol` |
| 本地有·官方无（2） | `unitsCr`、`dimensionType` |
| 命名不一致 | `unitsCr` ↔ 官方 `unitsGr`；`dimensionType` ↔ 官方 `pkgDimensionType` + `dimensionsType` |

## 4. 已决策 / 已关闭（归档，无需再核）

| 项 | 结论 |
|---|---|
| `request` 包裹层（官方复杂工具把参数包在 `request` 对象里） | **保持现状**：只服务自有客户端，不做解包。官方 MCP 是对 Open API 的薄封装（POST 型→包裹 30 个、GET 型→扁平 19 个），本地 13 个工具对应官方包裹式，按官方 schema 生成的客户端不保证可用；自研扁平客户端不受影响 |
| `reviews` vs `ratings` 命名 | **暂不处理**（涉 2 处：`competitor_lookup`/`product_research` 入参 `order.field` 枚举；`traffic_extend` 返回 `avgReviews`） |
| `traffic_listing_stat` 响应 `asin` 恒为 `null` | **已修**：改为回显输入 `asinList` |
| `product_node.month` | **已修**：官方支持且有效，本地有意不支持 → 已从 `app/tools.json` 移除该参数并清理 handler 死传参 |
| `keyword_conversion` 响应 `order` 硬编码 | **关闭（非问题）**：实测官方响应 `order={"field":"","desc":true}`，与本地逐字节一致 |
| `variation` 的 Y/N 语义 | **关闭**（已确认无问题） |
| `aba_research_*` 的 date 口径 | **保持本地「年+月+周」** |
| `market_research` 输出字段体系（官方 102 / 本地 32） | **保持现状**：不对齐官方 102 字段体系（属「命名体系不同」，对齐等于重写 transformer），本地继续用现有 32 字段；入参集与官方一致 |
| `traffic_listing_stat` 是否增加单数 `asin` 输入 | **不增加**：保持 `asinList` 单一入参（响应已回显 `asinList`）；官方 MCP 的单数 `asin` + 空转 `month` 不追随 |
| 站点分组严格校验 / 分页口径 / `order` 回显 / 上游 4xx 语义 / 代理工具重名 / 三处 transformer 缺 `require` / `traffic_listing` 页码回显 | **均已修复**（详见历史轮次记录，本轮不再罗列） |
