一、技术选型

1.1 总体选型建议

层选型理由
后端主框架Spring Boot 3.x（Java 17+）架构图已标注；事务/计费一致性、连接池、生态成熟，适合网关+计费场景
MCP/HTTP 网关Spring WebFlux 或 Spring MVC + SSE支持 SSE 流式响应与高并发透传；JSON-RPC 2.0 可自行实现或用 modelcontextprotocol/java-sdk
官网前端Vue 3 + TypeScript + Vite + Pinia（或 React，二选一待确认）官网+工作台交互复杂度中等，SPA 合适；图表用 ECharts
管理后台Vue 3 + 成熟 Admin 模板（如 vben / naive-ui-admin）表格/表单密集，复用组件库提速
数据库MySQL 8.0（InnoDB）计费流水需要事务与对账能力
缓存/限流/会话池Redis 7（ZSET / LIST / GET-SET）架构图既定方案
ORMMyBatis-Plus 或 Spring Data JPA团队熟悉度决定，建议 MyBatis-Plus（报表类查询灵活）
第三方调用异步 HTTP 客户端（Spring WebClient / OkHttp）+ Resilience4j超时、重试、熔断隔离第三方故障
采集脚本Node.js（原型图标注）或 Java 定时任务类目树采集，写 Redis 队列 + MySQL
支付微信支付 / 支付宝官方 SDK（服务端回调验签）原型既定支付方式
部署Docker + 单机/2 节点起步（云服务器），Nginx 反代 + TLS；预留 K8s 演进首期规模小，控制成本
可观测性结构化日志 + Prometheus + Grafana + 告警（链路追踪可选 SkyWalking / OTel）调用量/扣点/缓存命中率/第三方成功率监控
CI/CDGit 仓库 + GitHub Actions 或 Jenkins，镜像构建发布基础工程化

1.2 关键设计要点

  1. 网关横切链顺序固定：认证 → 限流 → 缓存 → 扣点 → 转发 → 转换 → 写缓存，全部实现为可插拔过滤器，MCP 与 REST 端点共享。
  2. 扣点一致性：事务内执行「余额扣减（乐观锁/行锁）+ usage_record 写入」；失败回滚、不写缓存；幂等键防重复扣点。
  3. 缓存键归一化：provider + api + 参数规范化（ASIN 大写去重排序、剔除分页参数）后 SHA-1 / SHA-256。
  4. 会话池调度：Redis LIST + 游标轮询；单账号连续失败自动摘除并告警，冷却后恢复（熔断）。
  5. 工具注册表：tools.json 落库 + 管理后台维护，tools/list 动态返回，新增接口免发版。

二、安全架构

2.1 分层安全设计

层措施
边界 / 传输全站 HTTPS（TLS 1.2+，HSTS）；Nginx 统一入口；隐藏第三方源站细节
Web 认证官网/后台：邮箱+密码登录，密码 Argon2 / bcrypt 存储；会话用短期 JWT（HttpOnly Cookie 或 Authorization Bearer）+ 刷新机制；登录失败次数限制（防暴力破解）
API 认证MCP / REST 用 secret-key；服务端只存 Key 哈希（SHA-256）+ 前缀明文，明文仅创建时展示一次；Key 支持即时停用
授权用户侧：只能访问自己的余额/密钥/流水；管理后台：RBAC（超管/运营/财务），敏感操作二次确认
限流与防滥用用户级 5 QPS 滑动窗口；全局 QPS 上限防 DDoS；IP 级粗粒度限流；注册接口加验证码/频控
输入校验JSON Schema 校验 MCP 工具参数；SQL 参数化；输出编码防 XSS
支付安全订单服务端生成，金额不可由前端传入；回调严格验签 + 幂等处理；防重复到账
敏感数据第三方账号 cookie 加密存储（AES-GCM，密钥走 KMS / 环境变量隔离）；Redis 开启认证与内网隔离；日志脱敏（Key / cookie / 邮箱）
审计管理后台关键操作审计日志；扣点流水不可篡改（append-only + 对账脚本）
依赖安全依赖漏洞扫描（OWASP Dependency-Check / Snyk），最小化第三方库

2.2 高风险项与建议（需陈总决策）

#风险影响建议
R1 第三方数据源采用挂 cookie 模拟登录态，违反选品软件服务条款可能性高，存在封号、法律（不正当竞争/数据爬取）风险 高 平台业务连续性 + 法律合规 优先评估官方开放接口（如 open.sellersprite.com 开放接口规范，架构图脚注已提及）或商务合作授权；短期若沿用，需多账号冗余 + 故障熔断 + 法务评估
R2 积分即资产，扣点/充值涉及资金 中 财务损失 / 纠纷 全流水对账、退款流程、每日对账任务
R3 cookie 池泄露 = 第三方账号批量失陷 中 数据源中断 加密存储 + 最小访问权限 + 轮换机制
R4 MCP 参数被大模型侧注入异常值 中 接口异常 / 越权 严格 JSON Schema + 白名单（marketplace 枚举、ASIN 格式校验）
R5 域名备案与支付资质（境内主体收单） 中 上线阻塞 提前启动 ICP 备案、微信/支付宝商户进件
