MCP 请求完整时序 一次工具调用的生命周期
步骤环节说明
1 MCP Client → /mcp 大模型发起 tools/call，携带工具名与参数（如 competitor_lookup：marketplace=US、asins=[...]）
2 认证 读取 secret-key → 查询 user_account（状态必须为 ACTIVE）未过即拒绝
3 限流 Redis ZSET 滑动窗口：同一 userId 1 秒窗口内 ≤ qps_limit（默认 5）超限返回 429
4 缓存查询 cacheService 计算缓存键（provider + endpoint + 参数 SHA1）→ Redis GET 命中：直接返回，不扣点不调第三方
5 会话轮询 缓存未命中 → pickSession(SELLERSPRITE) 从 Redis list 轮询选择一个账号登录态（cookie）
6 转发第三方 构造卖家精灵原生请求，携带所选会话的 Cookie / UA / Referer 发送 HTTP 请求
7 数据转换 transformers 将第三方响应重组织为标准 MCP 结构（字段重命名 / 类型转换 / 趋势数组化）
8 扣点 + 落库 读取接口定价（如 COMPETING_LOOKUP=10 点）→ 事务内扣减余额 + 写 usage_record
9 写缓存 转换结果写入 Redis，TTL 默认 300s，供后续请求命中
10 MCP Server → Client 返回 JSON-RPC 结果：structuredContent 携带标准化数据，模型组织成自然语言答案
数据存储设计 MySQL 持久化 + Redis 高速层

🛢 MySQL（持久化）

  • user_account用户 / 密钥 / 余额 / QPS / 角色
  • api_endpoint_pricing接口定价（每接口点数）
  • usage_record调用明细 / 扣点流水
  • amz_category亚马逊类目树（采集脚本写入）
  • 订单 / 充值记录官网后台（规划）

⚡ Redis（高速层）

  • mcp:ratelimit:{uid}限流滑动窗口 ZSET
  • mcp:cache:{provider}:{api}:{hash}第三方响应缓存（TTL 300s）
  • mcp:session:{provider}多账号登录态 LIST（轮询池）
  • mcp:session:cursor:{provider}轮询游标计数器
  • amz:category:crawl:*类目采集任务队列
缓存优先级说明：同一查询条件（marketplace + asins 集合）只取最新结果入缓存；用户量增大后大部分热查询直接命中缓存，显著降低对第三方选品软件的调用量。缓存键已对 ASIN 大小写 / 顺序做归一化，分页参数不影响缓存命中。
